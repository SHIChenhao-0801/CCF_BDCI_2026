\section{Method}
\subsection{Framework completion contract}
The implementation modifies JiuwenSwarm and uses the real openJiuwen Manager and execution/reporting modules. The default PAPER factory connects the existing local Provider to the artifact adapter. Direct completion, polled completion, and recovery of active tasks share a finalizer; persisted public status follows the task store rather than an earlier Provider snapshot. Existing failed tasks are preserved. A blocking decision retains the package and audit record instead of exposing a premature completed state.

The five gate rules are: APG001, a nonempty ordinary final PDF; APG002, parsable Manager state with successful terminal Reporting; APG003, existing declared artifacts contained within the allowed run root, with unsafe absolute or traversal paths rejected; APG004, parsable model-call records with unique identifiers and nonnegative integer input/output tokens that can be aggregated; and APG005, comparison of compiled citation and bibliography keys when reliable AUX exists. Without reliable AUX, APG005 is marked skipped, not passed. A blocker failure rejects completion. The gate uses no model calls. Audits at the run and package locations are each written atomically; this is not a cross-file transaction.

\subsection{Paired reasoning protocol}
The frozen, self-generated dataset has 36 items split into six development, six pilot, and 24 evaluation items. Evaluation includes eight items per family and 12 easy/12 hard labels. There is no training or weight update. Sequential arithmetic requires an exact integer. Satisfiable conjunctive normal form requires a full binary assignment; all satisfying assignments are accepted. Positive-weight graph tasks require a valid shortest path and a matching declared cost; tied optimal paths are accepted. Invalid JSON, missing fields, and invalid answer schemas remain failures rather than exclusions.

For evaluation item $i$, the initial answer is $a_i$. If it is correct, both final arms reuse it without an extra call. Otherwise each arm receives the problem, that same answer, and one reconsideration request. The diagnostic arm additionally receives the first applicable constraint error: an arithmetic mismatch category, an unsatisfied-clause index, an invalid graph/path condition, a path-cost mismatch, or a nonoptimal-path category. The diagnostic does not include the expected integer, a satisfying assignment, an optimal path, or its cost. The checker necessarily knows the verification oracle locally; that is different from forwarding an oracle answer to the solver. Error ordering and payloads are retained in the runner for inspection.

The control therefore matches extra \emph{calls}, not tokens, wall time, or monetary cost. Both arms use one shared initial answer, and each initially incorrect item receives exactly one attempt per arm. Let $g_i,d_i\in\{0,1\}$ denote final correctness. Our principal contrast is
\begin{equation}
\widehat{\Delta}=\frac{1}{24}\sum_{i=1}^{24}(d_i-g_i).
\end{equation}
We report exact two-sided McNemar testing on $b=\sum_i d_i(1-g_i)$ and $c=\sum_i g_i(1-d_i)$: conditional on $b+c$, the null reference is a binomial distribution with probability $1/2$. Marginal Wilson intervals use $z=1.96$ and $n=24$; they describe accuracy uncertainty, not the paired difference. Initially correct answers are retained, so final accuracy cannot fall below initial accuracy by design.

\subsection{Runtime and accounting}
The solver uses the returned model identifier \texttt{deepseek-flash}, temperature zero, disabled thinking, a 2,048-output-token cap, non-streaming responses, and no automatic request retry. A returned identifier is not a frozen vendor-weight version. Each actual reply retains response identifier, content, finish reason, usage, cache-hit tokens, and client latency. Started/returned records describe one call and are not counted twice. The child runner appends measured usage under the public task identifier and separate Manager node reference; completed cache/resume records do not trigger new requests or duplicate entries. Missing usage remains a failure.

PreparedCode copies four frozen public files and runs an offline smoke check. A real execution subprocess then performs the study. Optional ICLR Reporting delegates to the upstream writer/verifier, exposes already-measured nested confidence bounds as scalar metrics for the unchanged checker, and materializes task-local styles and concise writing guidance. Once all seven sections exist, real compilation precedes bounded optional polishing. After a normal writer return, complete sections without a PDF permit one existing compile CLI invocation; absent materials, compiler errors, or timeout do not synthesize success. The installed SDK and gate rules remain unchanged.
